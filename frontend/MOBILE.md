# MeetingIQ mobile app

The phone app is the same React app as the website, packaged with [Capacitor](https://capacitorjs.com) as a native Android and iOS app. It talks to the same FastAPI backend.

```
frontend/
├── capacitor.config.json   app id (com.meetingiq.app), name, web build folder
├── android/                Android Studio project (generated by Capacitor, committed)
└── ios/                    Xcode project (generated by Capacitor, committed)
```

## How the app finds the backend

The website calls the server it's served from. The app can't do that, so on first launch it asks for the **server address** and remembers it (Settings → Server). It checks that the address answers as a MeetingIQ backend before saving.

| Where the backend runs | Address to enter |
|---|---|
| A laptop on the same Wi-Fi as the phone | `http://<laptop IP>:8000`, e.g. `192.168.1.20:8000` |
| A hosted server | `https://meetingiq.example.com` |
| Android emulator, backend on the same computer | `10.0.2.2:8000` |

### Running the backend for the phone

The phone has to reach the backend over the network, so start it on all interfaces instead of only `localhost`:

```powershell
cd backend
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Find the laptop's IP with `ipconfig` (Windows, "IPv4 Address") or `ipconfig getifaddr en0` (macOS). If the phone can't connect, allow Python/port 8000 through the laptop's firewall, and check both devices are on the same Wi-Fi (guest and university networks often block device-to-device traffic).

The backend already accepts requests from the apps (`http://localhost` on Android, `capacitor://localhost` on iOS; see `CORS_ORIGINS` in `backend/app/config.py`).

## Building

Requirements: Node 22+, and **Android Studio** for Android, **a Mac with Xcode** for iOS.

```powershell
cd frontend
npm install
```

**Android**

```powershell
npm run mobile:android
```

This builds the web app, copies it into `android/`, and opens Android Studio. Press **Run** to install it on a connected phone (USB debugging on) or an emulator. **Build → Generate Signed App Bundle / APK** produces a file to share or publish.

**iOS** (on a Mac)

```bash
npm run mobile:ios
```

This opens Xcode. Choose your team under **Signing & Capabilities**, then **Run**.

After changing the React code, run `npm run mobile:sync` (or the platform command again) so the native projects get the new build.

## Differences from the website

- **Settings** in the navigation, for the server address. On the website, Settings just says the server is set by the site.
- **No "Print or save as PDF"**: phone web views can't print.
- **Android back button** goes back a page, and closes the app from the first page.
- Layout keeps clear of the notch and home indicator.

## Plain http and security

A laptop on Wi-Fi serves plain `http://`, which phones block by default, so the projects allow it:

- Android: `android/app/src/main/res/xml/network_security_config.xml` permits cleartext traffic, and the app is served as `http://localhost` (`androidScheme: "http"`) so calls to an `http://` server aren't blocked as mixed content.
- iOS: `ios/App/App/Info.plist` sets `NSAllowsLocalNetworking` and `NSAllowsArbitraryLoadsInWebContent`, and explains local-network access (`NSLocalNetworkUsageDescription`), which iOS asks the user to allow.

Recordings sent over plain http on a shared network can be read by others on it. For a published app, use a hosted **https://** server and remove these exceptions.
